Example: User turns ON LED for board_01

1. User clicks "Turn ON" button on dashboard (?board_id=board_01)
   ↓
2. JavaScript sends POST to: /control_led/ with board_id=board_01 and action=on
   ↓
3. Django view calls: send_led_command('ON', 'board_01')
   ↓
4. MQTT Manager generates topic: "thaitechzone/board_01/control/led"
   ↓
5. MQTT Manager publishes "ON" to topic
   ↓
6. MQTT Broker routes message to subscribers
   ↓
7. ESP32 board_01 receives message (subscribed to "thaitechzone/board_01/control/led")
   ↓
8. ESP32 turns LED ON (digitalWrite(LED_PIN, HIGH))
   ↓
9. ESP32 publishes state to "thaitechzone/board_01/status/led" with payload "ON"
   ↓
10. Django receives state message via MQTT callback
    ↓
11. Callback extracts board_id = "board_01" from topic
    ↓
12. Database updated: Device(board_id='board_01', is_on=True)
    ↓
13. Dashboard auto-refreshes and shows LED is ON

Note: board_02 and living_room are NOT affected because they subscribe to
      different topics!

║                          KEY BENEFITS                                         ║
╚═══════════════════════════════════════════════════════════════════════════════╝

✅ Multiple Boards:    Each ESP32 has unique topics
✅ No Conflicts:       Commands go to specific board only
✅ Data Separation:    Sensor data stored per board_id
✅ Easy Management:    Simple URL parameter to switch boards
✅ Scalable:           Add unlimited boards
✅ Flexible Naming:    Use meaningful names (living_room, greenhouse_1, etc.)
